\section{实验环境与复现流程}

考虑到FreeFlow同时涉及桌面端、后端、智能合约与外部IPFS服务，本文将实验划分为两类可复现任务：一类是基于本地数据集的检索排序离线评估，另一类是基于Hardhat本地链的智能合约自动化测试。前者用于验证链上资源检索与排序算法的有效性和性能，后者用于验证发布、购买和访问控制等链上核心业务逻辑。

实验过程已整理为可直接运行的脚本，检索排序实验命令为\texttt{pnpm --filter freeflow-web25-backend run experiment:ranking}，合约测试命令为\texttt{pnpm --filter @freeflow/contracts run test}，也可以通过\texttt{papers/Latex-Mine/scripts/run-thesis-experiments.sh}统一执行。实验生成的指标数据会自动写入\texttt{papers/Latex-Mine/figures/data/}目录，供本章图表直接读取。

从实验结果可以看出，单纯依赖SQL字段包含匹配虽然开销最低，但在拼写扰动、空格扰动和链上复杂身份查询场景中会出现明显漏召回，Zero Result Rate达到12.90\%。仅文本评分方法能够处理一部分模糊查询，但由于缺少身份字段特征，对Token ID、合约地址、CID和resourceKey等链上定位查询支持不足，其MRR和nDCG@10分别只有0.8306和0.8237，且Zero Result Rate进一步上升到16.13\%。

当加入链上身份字段后，Zero Result Rate下降到0，MRR从0.8306提升到0.9758，nDCG@10提升到0.9646，说明绝大多数查询都能在首位或前两位命中目标资源。完整排序算法在此基础上继续引入新鲜度和热度特征，在Precision@10、MRR和nDCG@10上保持与文本+链上身份字段方法一致的总体表现，同时为在线检索结果补充了业务可解释因子，说明新增排序特征没有破坏结果稳定性。

\section{本章小结}

本章基于可复现脚本完成了FreeFlow系统的实验验证。结果表明，智能合约核心逻辑已经能够稳定支撑作品发布、购买与权限控制；链上资源排序模块在引入身份字段后，MRR提升到0.9758、nDCG@10提升到0.9646，并将Zero Result Rate降至0；在500条候选规模下，完整排序算法仍可保持36.09 ms的平均响应时间。综合来看，FreeFlow已经具备较完整的链上音乐发布、访问和检索能力。
