\newcommand{\abstractCN}{
    随着数字音乐发行方式和区块链技术的发展，传统音乐平台在创作者发行流程、版权凭证、收益分配和资源访问控制等方面仍存在一定的中心化依赖。针对上述问题，本文设计并实现了一个基于区块链与IPFS的链上音乐发行与播放系统FreeFlow。系统采用Electron与React构建桌面端应用，采用Node.js、Express、Prisma和PostgreSQL构建Web2.5后端服务，采用Solidity智能合约实现音乐资源发布、ERC-1155访问凭证、购买授权和收益分账，并通过Pinata/IPFS保存音频、封面和metadata资源。系统面向创作者提供作品草稿管理、素材上传、metadata生成、链上发布和访问状态查询等功能，面向听众提供链上资源检索、详情查看、购买访问权、播放、评论、下载和链上音乐库管理等功能。

    为提升链上音乐资源的可检索性，本文进一步设计了链上音乐资源检索与排序模块。该模块综合考虑标题、艺术家、专辑、流派、描述等文本字段，以及合约地址、Token ID、交易哈希和IPFS CID等链上身份字段，通过查询归一化、候选召回、特征评分、模糊相似度、新鲜度和热度计算完成排序，并返回可解释的排序原因。系统测试从智能合约自动化测试和检索排序离线评估两个方面进行验证。结果表明，合约自动化测试4项全部通过；在包含26条资源和44个查询的评估集上，完整排序算法的MRR达到0.9773，nDCG@10达到0.9327，在500条候选规模下平均响应时间为23.27 ms，系统能够完成从创作者发布到用户购买播放的链上音乐业务闭环。
}

\newcommand{\abstractEN}{
    With the development of digital music distribution and blockchain technology, traditional music platforms still rely heavily on centralized services in creator publishing, copyright credentials, revenue distribution, and access control. To address these issues, this thesis designs and implements FreeFlow, an on-chain music publishing and playback system based on blockchain and IPFS. The system uses Electron and React to build the desktop client, Node.js, Express, Prisma, and PostgreSQL to build the Web2.5 backend, Solidity smart contracts to implement music publishing, ERC-1155 access credentials, purchase authorization, and revenue splitting, and Pinata/IPFS to store audio, cover images, and metadata resources. The system provides creators with draft management, asset uploading, metadata generation, on-chain publishing, and access status checking. It also provides listeners with on-chain resource retrieval, detail browsing, access purchase, playback, comments, downloading, and on-chain music library management.

    To improve the retrievability of on-chain music resources, this thesis also designs an on-chain music resource retrieval and ranking module. The module considers both textual fields such as title, artist, album, genre, and description, and on-chain identity fields such as contract address, token ID, transaction hash, and IPFS CID. It performs ranking through query normalization, candidate retrieval, feature scoring, fuzzy similarity, freshness, and popularity calculation, and returns explainable ranking reasons. The implementation is evaluated through smart-contract automation tests and offline retrieval experiments. The results show that all four contract tests pass, the full ranking algorithm reaches an MRR of 0.9773 and an nDCG@10 of 0.9327 on a benchmark with 26 resources and 44 queries, and the average latency remains 23.27 ms with 500 candidates.
}
